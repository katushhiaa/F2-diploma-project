# ТЕХНІЧНА КАРТКА КВАЛІФІКАЦІЙНОГО ПРОЄКТУ
**(Thesis Proposal)**

---

## 1. Попередня робоча назва проєкту
* **Українською мовою:** Веб-платформа для колаборативного читання з агрегацією цитат та синхронізацією темпу читання групи.
* **English language:** Web Platform for Collaborative Reading with Quote Aggregation and Group Reading Pace Synchronization.

---

## 2. Актуальність та проблематика
Наявні цифрові сервіси супроводу читання (Goodreads, StoryGraph) реалізують пасивну модель каталогізації: фінальні оцінки та статичні списки без підтримки спільного опрацювання тексту в процесі читання. Проєкт вирішує такі інженерні та алгоритмічні задачі:

* **Блокування основного потоку виконання (Event Loop) важкими операціями.** Виконання оптичного розпізнавання тексту (OCR) безпосередньо на веб-сервері створює критичне навантаження на CPU та блокує обробку паралельних HTTP-запитів. Задача вирішується впровадженням асинхронного чергового механізму з контрольованим рівнем паралелізму та можливістю горизонтального масштабування воркерів.
* **Семантична неконсистентність розпізнаного контенту.** Текстові фрагменти, завантажені різними користувачами з різних видань і за різної якості зйомки, містять оптичні артефакти та розбіжності верстки. Задача — нечітке зіставлення рядків (Fuzzy String Matching) для знеособленої кластеризації цитат і побудови рейтингу популярності без деанонімізації користувачів.
* **Управління спільним станом у реальному часі та контекстне приховування даних (Spoiler Prevention).** Синхронізація темпу читання групи потребує аналізу часових рядів прогресу учасників, прогнозування часу завершення книги та динамічної серверної фільтрації коментарів і цитат відповідно до поточної сторінки кожного клієнта.

---

## 3. Сформована ідея продукту
**Архітектурний тип системи:** Подієво-орієнтована розподілена веб-платформа реального часу з асинхронним черговим конвеєром комп'ютерного зору (*Event-Driven Real-Time Web Platform with Asynchronous Task Queue for OCR Processing*).

Система спроєктована за сервісно-орієнтованим підходом з чітким розділенням відповідальності:
* **REST API шар** — транзакційні CRUD-операції з каталогом книг, профілями користувачів, відгуками та персональною бібліотекою.
* **Черговий контур (Message Broker / Worker Pool)** — фонова обробка ресурсомісткого оцифрування фрагментів сторінок без деградації латентності API; підтримує горизонтальне масштабування додаванням інстансів воркера.
* **WebSockets шар** — постійне двостороннє з'єднання для синхронізації прочитаних сторінок у групових кімнатах і трансляції подій у реальному часі.
* **Контур персистентності** — документоорієнтована СУБД зі складеними індексами та Aggregation Pipeline для статистичного аналізу без розкриття персональних зв'язків.
* **Контур спостережуваності (observability)** — структуроване логування та метрики стану черги й воркерів, що дозволяють діагностувати збої обробки до їх ескалації.

## 4. Детальний опис функціоналу (Core Features)
1. **Ідентифікація та каталогізація видань через штрихкодову детекцію.** Потоковий відеозахоплювач штрихкодів стандарту EAN-13/ISBN на клієнті з подальшим зверненням до зовнішніх REST API (Google Books / Open Library) для автоматичного формування метаданих книги.
2. **Асинхронний конвеєр оптичного оцифрування уривків (ROI Canvas + Worker OCR).** Клієнтське кадрування області інтересу (Region of Interest) на базі HTML5 Canvas API з передачею фрагмента в чергу Redis та фоновим розпізнаванням тексту бібліотекою Tesseract.js; задачі — ідемпотентні, з механізмом retry та dead-letter чергою для задач, що вичерпали ліміт спроб.
3. **Персональна бібліотека нотаток за принципом Privacy by Design.** Обов'язкове збереження всіх оцифрованих цитат в ізольованому персональному сховищі з можливістю активації опції публічного внеску (`contributeToStats: true`), за якої цитата враховується в агрегації виключно як знеособлений лічильник без розкриття автора.
4. **Нечітке зіставлення та агрегація популярності уривків (Fuzzy Matching Engine).** Нормалізація та кластеризація публічно врахованих цитат за метриками відстані Левенштейна та коефіцієнта Джаро-Вінклера для формування об'єднаного рейтингу уривків без розкриття користувачів, які їх зберегли.
5. **Алгоритмічна синхронізація темпу читацької групи.** Аналіз історії прогресу сесій (сторінок за одиницю часу), прогнозування індивідуального фінішу та формування динамічного графіка рекомендованого темпу кімнати для одночасного завершення книги групою.
6. **Колаборативні кімнати читання з контекстним захистом від спойлерів.** Спільні сесії читання з реплікацією прогресу учасників у реальному часі через WebSockets та автоматичним серверним приховуванням коментарів і цитат, прив'язаних до сторінок, які ще не досягнуті поточним користувачем.
7. **Соціальний граф та захищений обмін контактами.** Пошук користувачів за нікнеймом із префіксною індексацією, перехід до профілю з текстових відгуків, протокол двосторонньої дружби (Pending/Accepted) та умовне розкриття Telegram-контакту виключно для взаємно підтверджених друзів.

## 5. Нефункціональні вимоги, надійність та безпека
Окремо від функціональних можливостей визначено вимоги до якості системи, що є предметом окремої оцінки під час захисту:

| Характеристика | Цільовий показник / підхід |
| :--- | :--- |
| **Продуктивність API** | p95 латентність транзакційних CRUD-запитів REST API — не більше 200 мс під типовим навантаженням |
| **Пропускна здатність OCR-конвеєра** | Обробка задачі розпізнавання не блокує основний Event Loop; горизонтальне масштабування через додавання інстансів воркера BullMQ з контрольованим рівнем паралелізму (concurrency) |
| **Надійність** | Задачі OCR — ідемпотентні, з механізмом retry та dead-letter чергою для задач, що завершились помилкою після вичерпання спроб |
| **Спостережуваність** | Структуроване логування (pino) для всіх сервісів; метрики глибини черги, часу виконання джоб і стану воркерів, що експортуються в Prometheus |
| **Безпека** | Автентифікація на основі JWT, валідація вхідних даних (Zod), обмеження частоти запитів (rate limiting) на публічних ендпоінтах |
| **Масштабованість БД** | Складені та часткові (partial) індекси MongoDB для швидкого пошуку за нікнеймом і фільтрації цитат; агрегаційні пайплайни виконуються асинхронно від основного потоку запитів |

## 7. Стратегія тестування та CI/CD
* **Unit-тестування (Vitest/Jest)** — алгоритми нечіткого зіставлення цитат, прогнозування темпу читання.
* **Integration-тестування (Supertest)** — REST API ендпоінти, взаємодія з MongoDB.
* **Навантажувальне тестування (k6)** — пропускна здатність OCR-черги під навантаженням, для перевірки цільових показників з розділу 5.
* **CI/CD пайплайн (GitHub Actions)** — послідовність стадій: `lint` → `unit-тести` → `integration-тести` → `build Docker-образів` → `deploy у staging-середовище`.
* **Контейнеризація (Docker Compose)** — окремі сервіси для API, воркер-пулу, MongoDB, Redis, з відтворюваним середовищем розробки та розгортання.
